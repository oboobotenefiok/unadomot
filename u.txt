==============================================================================
0. PURPOSE AND GROUND RULES
==============================================================================
Goal: make the codebase smaller, faster, safer to change and easier to onboard
onto, WITHOUT changing what users see. Consolidation is also a security fix here:
the duplicated auth helper is the reason suspended users, rate limits and PII
rules are inconsistent across the API.

Rules (non-negotiable)
 R1  Behaviour-preserving. A refactor commit changes structure, not behaviour.
     Intentional behaviour changes (security fixes from the review) go in
     separate commits and are labelled "fix:" not "refactor:".
 R2  Safety net first. Before moving code, add characterization tests that pin
     current API JSON shapes and key Flutter widget output. Do not refactor an
     untested area; write its test first (see section 9).
 R3  One move per commit, green build after each commit. No mixed feature work.
 R4  Rule of three. Merge code only when the same logic exists 3+ times or is
     a security/consistency-critical rule (auth, error mapping, money). Do not
     merge things that merely look alike (e.g. a DB row type and a public DTO
     must stay separate types even if fields overlap).
 R5  Measure before and after. Fill the table in section 10. A refactor with no
     measurable win (fewer lines, fewer duplicates, faster build, faster
     request) needs a written reason.
 R6  Never edit an applied SQL migration (checksum). Add new ones.
 R7  Keep API contracts stable: same routes, same JSON field names, unless the
     review says otherwise (e.g. remove email/phone from public profile).

B0  Safety net. Add router-level tests (tower::ServiceExt::oneshot, real
    Postgres) that pin status code + JSON shape for every current route. Fail
    when DATABASE_URL is missing. This is the harness for everything below.

B1  AuthUser / AdminUser extractors  (kills 6 authorize + 4 admin_roles copies;
    review IDs P0-D, T4-AUTHZ)
      pub struct AuthUser { pub id: Uuid }
      impl FromRequestParts<AppState> for AuthUser {
          type Rejection = ApiError;
          async fn from_request_parts(parts: &mut Parts, s: &AppState)
              -> Result<Self, ApiError> {
              let token = bearer(parts)?;                 // one place
              let claims = verify_session(token, &s.config.jwt_secret)?;
              if !s.users.is_active(claims.sub).await? { return Err(ApiError::Unauthorized) }
              Ok(AuthUser { id: claims.sub })
          }
      }
      pub struct AdminUser(pub AuthUser);   // same + users.is_admin / admin check
    Handlers become `async fn create_comment(user: AuthUser, State(s): ...)`.
    Delete every local authorize()/error() helper. Cache is_active with a
    30-60 s moka TTL cache keyed by user id (invalidate on suspend).

B2  One ApiError  (kills 4 error() helpers and 84 map_err sites; T4-LOG)
      #[derive(Debug, thiserror::Error)]
      pub enum ApiError {
          Unauthorized, Forbidden, NotFound, RateLimited,
          Conflict(&'static str), Validation(Vec<FieldError>),
          Internal(#[source] anyhow::Error),
      }
      impl From<sqlx::Error> for ApiError   // unique violation -> Conflict,
                                            // RowNotFound -> NotFound,
                                            // else Internal
      impl IntoResponse for ApiError        // builds {"error":{"code","message"}}
                                            // and tracing::error!(source) for
                                            // Internal ONCE, with request id
    Repositories return Result<T, RepoError> (thiserror), converted by From.
    Use `?` everywhere; no `.map_err(|e| X(e.to_string()))`.

B3  One AppState  (replaces ProfileState/CommentState/CallState/Verification-
    State; removes the "pool only if DB configured" branching in main.rs)
    AppState holds Arc<dyn ...Repository> for users, listings, messaging,
    comments, profiles, calls, verification, reports + media signer + limiter +
    config. Every router is `fn router() -> Router<AppState>`; `app()` merges
    them then applies the single layer stack (B5).

B4  Move SQL out of handlers into repositories (profile 21 queries, comments 12)
    New traits: ProfileRepository, CommentRepository. Return domain/DTO types.
    This also fixes the f64-vs-NUMERIC price bug (use Decimal in one shared
    ListingSummary row type used by browse, my-listings, public profile,
    favorites). Split OwnProfile and PublicProfile types so email/phone can
    never be serialised publicly (compile-time guarantee).

B5  One layer stack on the MERGED router (fixes P0-D):
      Router::new().merge(auth).merge(listings)...
        .layer(TraceLayer)        // + request-id
        .layer(Cors)              // default deny
        .layer(DefaultBodyLimit)  // 1-2 MB; per-route larger for uploads
        .layer(TimeoutLayer)      // 15 s
        .layer(CompressionLayer)
        .layer(SecurityHeaders)
        .layer(RateLimit)         // classes: auth, write, read, upload
    Rate-limit classes live in one table (route prefix -> class -> limit).

B6  Typed Config  (kills 27 scattered env::var; P1-1, P1-2)
    Config::from_env() -> Result<Config, ConfigError> parsed ONCE; APP_ENV enum
    (Development|Staging|Production, default Production when FLY_APP_NAME set);
    secrets as `Secret<String>` (redacted Debug); validation: min entropy,
    placeholder blocklist, refresh != jwt, required-in-production list.
    docs/configuration.md is GENERATED from a `Config::describe()` table and a
    test asserts .env.example keys == Config keys (single source of truth).

B7  Delete Unconfigured* adapters from production code. Production boot fails if
    a required dependency is missing. Tests use fakes in tests/support.

B8  Value objects + one validation module. Email, Username, Phone, Money,
    ListingCode, State/LGA (from domain/nigeria.rs) validated once; handlers
    take validated types (ValidatedJson<T>). Removes the repeated trim/len
    checks in profile/comment/messaging/listings handlers.

B9  Shared pagination: Cursor { created_at, id } + `Page<T> { items, next }`
    used by messages, comments, browse, favorites, admin lists (fixes tie-skip
    bug and the comments "oldest 200" problem).

B10 Split http/mod.rs (1,337 lines) by route group into http/routes/*.rs plus
    dto/ and middleware/. Target: no file > 400 lines (lint in CI).

B11 Migrations: do not rename applied files. From the next one on, use ONE
    scheme (recommend sequential 0013_ ... and document it in
    migrations/README.md; make sure 20261126000x do not sort before it - add a
    test that lists migrations and asserts strictly increasing versions when
    sorted as sqlx does). Add `cargo sqlx prepare` + `--check` in CI after
    moving to query!/query_as! macros (compile-time schema check).

B12 Optional: Cargo workspace (domain / application / infrastructure / api).
    Do it last; measure incremental build time before/after.

6. OPTIMISATION: SPEED, SIZE, RESOURCE USE
==============================================================================
6.1  API latency and database
  - Kill N+1 and chatty reads: build conversation list, listing + media, comment
    + reactions with a single query each (LEFT JOIN LATERAL / json_agg), not one
    query per row. Return listing SUMMARIES on list endpoints (no full
    description/all media), full object only on detail.
  - Indexes (add via new migration): messages(conversation_id, created_at DESC,
    id); listing_media(listing_id, position); favorites(user_id, listing_id) and
    (listing_id); listing_comments(listing_id, created_at DESC, id);
    listings(status, created_at DESC) WHERE deleted_at IS NULL; pg_trgm GIN on
    title/address for search; unique lower(username); refresh_tokens(user_id),
    (expires_at). Check EXPLAIN (ANALYZE, BUFFERS) for browse + inbox queries and
    keep results in docs/perf.md.
  - Keyset pagination everywhere (no deep OFFSET).
  - Avoid a DB hit per request for is_active: moka cache, 30-60 s TTL.
  - Pool: size to Neon limits (e.g. 5-10), acquire_timeout 5 s, idle_timeout,
    max_lifetime, statement_timeout (e.g. 5 s) via after_connect. If you use
    Neon's pooled (-pooler) endpoint, disable client-side prepared statement
    caching; if you use the direct endpoint, keep migrations on it.
  - Argon2 in spawn_blocking; tune memory/iterations to ~50-100 ms on the Fly
    machine; keep the dummy verify for unknown users.
  - Rate limiter: pooled redis ConnectionManager, atomic Lua (INCR+EXPIRE NX),
    no connection-per-request.
  - Read-mostly caching: Cache-Control + ETag on public listing pages, sitemap
    and listing detail GETs; short TTL in-process cache for filter lists
    (states/LGAs are static: serve with long max-age).
  - Responses: tower-http CompressionLayer (gzip/br); keep JSON payloads small.
  - Background work off the request path: Google tokeninfo (shared reqwest
    client + timeout; later local JWKS verify), email sending (queue/tokio task
    with retries), media cleanup, token cleanup, listing expiry.
  - Chat/call polling: replace fixed-interval polling with SSE/WebSocket, or at
    least back off when the screen is idle/backgrounded and use ETag/`since`.
6.2  Rust build speed and binary
  - cargo-chef / BuildKit cache for Docker; Swatinem/rust-cache in CI; mold
    (or lld) linker; sccache optional; `cargo nextest` for tests.
  - [profile.release] lto = "thin", codegen-units = 1, strip = true,
    opt-level = 3 (benchmark vs "s"); panic = "abort" only if no catch-panic
    needs it. Trim features on tokio/reqwest/redis/sqlx; run cargo-udeps and
    drop unused crates (e.g. confirm sha1 is still needed for Cloudinary).
  - Smaller image: distroless/cc or debian-slim without curl (use a Rust
    healthcheck subcommand `unadomot-api healthcheck`).
6.3  Flutter runtime
  - Startup: render the first frame immediately (splash), then initialise in
    parallel (Future.wait for storage restore, prefs, cache open); do not await
    network before first paint; lazy-init heavy plugins (flutter_webrtc,
    record, audioplayers, file_picker, maps) only when their screen opens.
  - Lists: ListView.builder / SliverList with itemExtent or prototypeItem where
    possible, `const` widgets, RepaintBoundary around cards, keys on items;
    rebuild narrowly (ValueListenableBuilder / Selector / Riverpod select), not
    whole 800-line State objects.
  - Images: cacheWidth/cacheHeight to display size, Cloudinary f_auto,q_auto,w_N,
    thumbnail vs full, precache the next carousel image, evict on memory warning.
  - Data: decode large JSON lists in `compute()`; sqflite writes in batches and
    transactions with indexes on the lookup columns; cap and prune the offline
    cache (TTL + max rows) and clear it on sign-out.
  - Network: debounce search (300 ms) and cancel in-flight requests; request
    only the fields/page size needed; coalesce duplicate calls (the transport's
    in-flight map); exponential backoff + friendly "waking server" state.
  - Size: ship an App Bundle (AAB) or `--split-per-abi`; enable R8 + resource
    shrinking; `--obfuscate --split-debug-info`; remove unused fonts/assets;
    audit with `flutter build appbundle --analyze-size`; set a size budget in CI.
  - Verify with DevTools (jank, rebuild counts, memory) on a mid-range phone;
    target first frame < 1 s warm, listing grid scroll without dropped frames.
6.4  Remove duplicated type definitions across tiers
  - Publish an OpenAPI 3 document from the Rust API (utoipa + utoipa-axum),
    version routes under /api/v1, and generate the Dart client/models from it in
    CI (openapi-generator or a lighter generator). This deletes hand-written DTOs
    and the class of "app and API disagree" bugs. Add a contract test that the
    committed openapi.json equals the generated one.

7. ENGINEERING FRIENDLINESS
==============================================================================
7.1  Onboarding in minutes: `just setup && just db-up && just api && just app`
     works from a fresh clone; seed script creates demo users/listings; .env
     generated from the Config table with safe dev defaults; docs/engineering.md
     explains structure, conventions and how to add an endpoint end to end.
7.2  Standards: rustfmt/clippy (-D warnings, pedantic where cheap), flutter_lints
     + very_good_analysis or similar; max file length 400 lines and max function
     length lint; conventional commits; ADRs for every cross-cutting decision
     (auth model, pagination, error shape, migrations scheme).
7.3  Architecture rules as tests: Rust - application/ must not import axum/sqlx
     (cargo-deny/`cargo modules` check or a simple grep test); Flutter -
     features/* must not import each other's ui/ (import_lint / custom_lint);
     only core/api may import `package:http`.
7.4  Testing pyramid with shared support code: Rust tests/support (test app,
     user/listing builders, fake clock/email); Flutter test/support (fake API,
     pumpApp helper with theme+localizations, golden helper); factories instead
     of copy-pasted setup. Targets: backend >= 75% on application+http,
     Flutter >= 60% on core+features/*/state, 100% of routes have a contract test.
7.5  Observability for developers: request id in every log line and response,
